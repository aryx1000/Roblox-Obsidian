Back to [[Knowledge/Index|Knowledge]]. These preferences are learned from all three projects.

- **Games:** [[Shift From Hell]], [[Grab & Run]] and [[Mutant Pet Lab]].

## Non-negotiables
- **Honesty above all.**
  - Never invent ids, results or tests.
  - Separate PASS / FAIL / BLOCKED / NOT TESTED, and mock vs real.
  - Say plainly when something wasn't verified.
- **Explicit approval for anything outward-facing:** publishing, visibility, creating places, products or passes, spending Robux, live data, HTTP or Studio API access.
- **Target discipline:** verify the PlaceId and owner before every edit. **Never touch GRAB N RUN!** (or another game) when working on one.

## Work style
- Long structured briefs with numbered phases and numbered final reports. **Follow the report format exactly.**
- **Checkpoint everything:** snapshot, git commit, then the state file.
- **Machine resources matter:** at most **3 Roblox Studio processes** (the Edit window counts) unless approved. Close stale windows and don't relaunch sessions needlessly.
- **Efficiency:** don't test every device; use the 4 representative sizes. Cosmetic polish waits for a later Figma/UI phase.
- **Keep going through the whole brief** unless genuinely blocked. When blocked, state the exact blocker and the action needed.
- When the owner repeats a brief that's already done, verify the state and say so; don't redo the work (e.g. a second publish).
