# Persistence

> [!danger] Safety rules
> Studio is **always Mock** (in-memory). Never enable Studio API access, never read or write production keys from Studio, no admin grants, no direct DataStore writes, no profile editing, no forced migrations.

| | Value |
|---|---|
| Live store | `MPL_PlayerData_PROD_V1`, scope `Production` |
| Key | `MPL_PROD_V1_<UserId>` |
| Schema | v3 (`PlayerDataSchema`) |
| Selection | `PersistenceSelector.Decide`: Studio→Mock; live + exact place/group/namespace→Production; anything else fails closed |
| Released | v88, 2026-10-14 |

## Behaviour
- **Load:** 3 retries; failure → LoadFailed (progress paused, saves refused). New profile only when the key is truly absent. Future schema fails closed.
- **Save:** optimistic `Revision` in `UpdateAsync` → SaveConflict blocks the session. Per-profile change counter; one save per profile at a time.
- **Autosave** 120 s (dirty only) · **Leave** saves then releases · **Shutdown** parallel `SaveAll` in 25 s.

## What is saved
Cash, Research, XP, creatures (id, species, trait, variant), discoveries, upgrades, research, assignments, onboarding, and the whole property (structures, pets, habitats, crops, care, eggs, incubators, stage, featured creature). Session-only: Specimen Supply cycle.
